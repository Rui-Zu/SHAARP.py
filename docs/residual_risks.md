# Residual risks — what v1.0.0 does not verify

The complement of the green stamps. `RELEASE GATE: PASS` + `MATRIX SWEEP: CLEAN` certify the
enumerated dimensions (suite, exe self-check, GUI smoke, the 312-cell case x functionality
sweep, sensitivity matrix,
referee gates, fidelity matrix, paper replication). This file lists what those stamps do NOT
cover — so a future session (or a user report) can tell a *known accepted limit* from a *new
defect*. The T3 lesson is the reason this file exists: the whole gate suite passed while
GaAs(111) polarimetry returned NaN at most angles, because the gates verified
enumerable dimensions and internal consistency — not ground truth at unenumerated points.

Ordered by how likely a real user is to hit each one.

| R13 | **A TRUE GUI HANG IS NOT DETECTABLE IN-PROCESS.** `Update` runs synchronously, so the Qt event loop does not come back to service a watchdog timer while a computation is in flight. An in-process time budget can therefore fail a run that is pathologically SLOW BUT FINISHING, while a run that never returns simply stalls with nothing to report. The offscreen harness in `tests/gui_harness.py` and the layout fences in `tests/test_gui_layout_integrity.py` exercise every control, but they inherit the same limitation. | catching an arbitrary hang would require driving each input combination in its own subprocess, at a large runtime cost. | a hang in an input combination outside the exercised set; it presents as the run never finishing rather than as a failure. | drive the suspect combination in a subprocess with `faulthandler.dump_traceback_later`, which turns a hang into a stack trace. |

Rows R12+ were appended later; numbering is stable (rows are never renumbered, because tests and

Maintenance rule: when a user report or a new evaluation layer converts one of these rows into a
confirmed defect, record it, fix it, fence it, and delete the row;
when a new *accepted* limit is discovered, add a row at the moment of discovery.

**Enforcement:** `tests/test_residual_risk_register_integrity.py` binds this file to the code —
every row must cite at least one anchor (a real path or `test_*` name), every anchor must be a file
the repository actually ships, and any module or test count claimed here must equal the live suite.
Prose that describes behaviour still reads perfectly well after the behaviour changes, so a register
without such a binding goes stale silently.
